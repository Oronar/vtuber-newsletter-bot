# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A daily/weekly VTuber mini-newsletter, **SIGNAL//BOOST**. The repo is mid-migration
between two implementations:

1. **The web edition (current direction).** A Jekyll site under `docs/`, published on
   GitHub Pages, whose issues are generated by the **`/new-issue` skill** (Claude does the
   web search and writing directly — no external API). This is where new work goes.
2. **The legacy bot (being retired).** `post_newsletter.py` + `.github/workflows/newsletter.yml`
   — a Claude-API-with-web-search script that posted the whole newsletter to a Discord
   webhook daily. The workflow is **disabled** and this path is superseded; kept for
   reference only.

## The web edition (docs/)

- **Live:** https://oronar.github.io/vtuber-newsletter-bot/ — GitHub Pages, **deploy from
  branch → `main` / `docs`** (Jekyll builds automatically; no Actions build step). `baseurl`
  is `/vtuber-newsletter-bot`; use `| relative_url` for internal asset paths.
- **Per-issue data:** `docs/_data/issues/NNN.json` (zero-padded, one file per issue).
- **Rendering:** `_includes/page.html` renders a full edition from one `issue` object;
  `_includes/story-card.html` is the shared numbered-story card (used by THE DISPATCH and
  INDIE FREQUENCIES). `docs/index.html` renders the **highest-numbered** issue, so the
  homepage is always the latest.
- **Permanent urls:** `docs/issues/NNN.html` is a one-line stub with front matter
  `permalink: /issues/NNN/`, giving every issue a stable url (`…/issues/NNN/`). Discord
  links point at these, so they must never change once published.
- **Styling:** `docs/assets/signalboost.css` holds only what inline styles can't —
  link `:hover`, the **CSS-only Tea Corner spoiler toggle** (hidden checkbox + `:checked`
  sibling; default = frost shown, click to decrypt), and a responsive tweak. The rest of
  the design lives in inline styles translated from the "SignalBoost v2" Claude-Design
  component. Raw design mockups are in `/mockups` (outside `docs/`, so unpublished).
- **Gotcha:** Liquid executes `{% %}` tags **inside HTML comments**. Never put a literal
  tag in a comment — a stray `{% include %}` in a comment caused infinite include
  recursion / a broken build twice during setup.

## Generating an issue — the `/new-issue` skill

`.claude/skills/new-issue/SKILL.md` is the single source of truth. Two modes:

- **`weekly`** — next issue number, write `docs/_data/issues/NNN.json` (`kind:"weekly"`) +
  the `docs/issues/NNN.html` permalink stub, then commit and **push to `main`** (Pages
  redeploys; Discord is notified). Confirm before the first push unless unattended.
- **`test`/`oneoff`** — write `docs/_data/issue-preview.json` only (`kind:"oneoff"` + a
  label); never touch the archive/homepage, never push. `page.html` shows a magenta
  "⚠ TEST ISSUE" banner whenever `kind != "weekly"`.

**Editorial invariants** (carried from the legacy prompt; read them in the skill before
loosening). Recency widened to **last 7 days** for the weekly cadence. Hololive/Holostars
capped at two stories; Nijisanji, Phase Connect, and indies must be represented (VShojo
closed 2025, PRISM closed 2024 — their talents are now independents). The **Tea Corner**
gossip section is permanent with four hard content lines (no unverified misconduct/abuse/
crime allegations against named people, no doxxing, no explicit NSFW, no real-person
mental-health/self-harm speculation) — web search often surfaces exactly this off-limits
drama, so filter it and use lighter debut/collab speculation.

There is **no local Ruby/Jekyll**. Preview with the emulator built during setup (renders
`_includes/page.html`); the real build only happens on Pages after a push.

## Publishing & Discord

`.github/workflows/discord-notify.yml` fires on a push to `main` touching
`docs/_data/issues/**` and posts the newest issue's **permalink** (not the body) to the
`DISCORD_WEBHOOK` secret. A commit message containing `[skip-discord]` suppresses it (for
infra/refactor commits — weekly commits must not include it). It can also be run manually
from the **Actions** tab (`workflow_dispatch`) to test the webhook.

Intended cadence: **weekly**, via a `/schedule` cloud **routine** (`SIGNAL//BOOST weekly`,
`trig_019bXS2oSSR8UfPQAMvrcB9Q`, cron `0 9 * * 1` = Mon 09:00 UTC / 5am EDT). **A routine
cannot push to `main`** — Claude Code routines may only push to `claude/*` branches (a push
to `main` 403s; this is *not* a missing-write-access problem, and the UI has no toggle to
lift it). So the pipeline is:

1. The routine runs the skill in `weekly` mode but its step 6 pushes the new issue on a
   `claude/issue-NNN` branch (**not** `main`).
2. `.github/workflows/publish-issue.yml` fires on that `claude/**` push, opens a PR, and
   **squash-merges it into `main`**. That merge redeploys Pages and triggers
   `discord-notify.yml`. It merges with a **PAT** (`AUTOMERGE_TOKEN` secret, repo-scoped:
   Contents + Pull requests read/write) on purpose — a `GITHUB_TOKEN` merge would *not*
   trigger `discord-notify.yml` (pushes by `GITHUB_TOKEN` don't start other workflows).

Requirements: run `/web-setup` locally once so cloud runs can push at all (syncs your `gh`
token, which has `repo` scope), and keep the `AUTOMERGE_TOKEN` secret valid. Cloud commits
are **unsigned** (signing keys never enter the sandbox) and authored as the connected GitHub
identity — expected, not a failure. The local `/new-issue weekly` path still pushes straight
to `main` (SKILL.md) since a local checkout has full write; only the routine takes the branch
detour.

## Legacy bot (reference)

`post_newsletter.py`: `anthropic` client + `web_search_20260209` tool → `chunk_message()`
→ ASCII-safe JSON to `DISCORD_WEBHOOK`. `newsletter.yml` ran it daily at `0 12 * * *` UTC
and is **disabled** (`gh workflow disable "VTuber Newsletter"`, not a code change).
`ANTHROPIC_API_KEY` and `DISCORD_WEBHOOK` are repo secrets. Superseded by the web edition.

## Repo conventions

Commits are **GPG-signed** (global `commit.gpgsign=true`). If signing fails with "Unusable
secret key", check the signing key's **expiry** first (it expired mid-2026 once and needed
renewing) before assuming an agent/passphrase problem.
